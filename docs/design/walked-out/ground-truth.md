## The concept (settled)

In Doug's convergence lane (Doug re-reviews a PR on each push and classifies each prior finding), a finding is `resolved` only when a deterministic check disproves it or the interdiff from the previous reviewed head to the current head touched the finding's cited code. Otherwise it is `persisted-by-construction` (cited code byte-untouched, so the defect cannot have moved) or `unknown(not-reconfirmed)` (cited code touched, nothing confirms the fix). Zero new model calls. Doug publishes its reader flip rate (how often the reader silently dropped a finding on untouched code) beside the miss rate. Andrew's rulings (2026-08-18): hunk identity NOW; reland-labeler bug fix backlogged (must land before any published number, not before the certificate); flip rate published alone by default. Choosing this design IS the ruling on the failed bar 1 (redesign, not repair).

Wedge: a halt signal an agent can trust, and a number incumbents will not publish.

## Constraints the concept has not accounted for (the live design questions)

1. **Where spans come from.** Three options, none free: (A) model-emitted `line_start/line_end` in SCHEMA → ADR-0013, PROMPT_HASH moves, "own pre-registration and its own run" (or declined-with-record), must be validated against the hunks actually sent (cite()-like check) or a hallucinated span silently produces a false `persisted`; diff-line vs head-line coordinates differ. (B) **Deterministic hunk index, no SCHEMA change**: at each read, hash every hunk of each file's patch by content (not `@@` numbers); identity for a finding = (pattern, file, the hunk-hash set of that file as read); at the next read, `persisted-by-construction` iff every hunk of the cited file is byte-identical; single-hunk files get exact grain; multi-hunk files with partial change → `unknown(not-reconfirmed)` unless re-emitted. Costs recall on multi-hunk files; needs no new network (patches are already fetched) and no model. (C) paid verify citations (#118) — rejected by "zero new model calls". Andrew's "hunk identity now" was ruled before option B was on the table.
2. **Retrospective validation is file-grain only.** Bars A/B validate the file-grain gate on the 43-unit sample; hunk-grain validates prospectively on rows emitted after the change. Don't let a file-grain pass be read as a hunk-grain pass. Bar A denominator ≤17 is below the plan's n=40; admissible as a point estimate (CP interval never gates) but must be said.
3. **Settle ⇒ resolved reverses rule 4.** Decide: keep `settled` as its own state outside the ratio (disproved ≠ author progress), or fold into "no action needed" for the agent's halt signal. Settle evidence exists only when the later read re-emitted the finding.
4. **Purity + caller.** Touched-hunk/interdiff evidence computed in the worker (or eval script) and passed in as rows; importer allow-list (`test_convergence.py:335-357`) must be amended for worker/store deliberately.
5. **Worker has no prior-verdict lookup and no interdiff.** Rendering three states on the check run at head N requires: prior reader-tier verdict for the PR (new store helper), its findings + hunk identity, and either the compare API or stored per-hunk hashes. `_replay_recorded` must render from rows too.
6. **Non-linear pairs (force-push/rebase)** need an explicit rule (likely `unknown(non-linear)`); renames/`previous_filename` break exact-path identity; prior read's coverage matters (cited hunk must have been inside what was sent in BOTH reads).
7. **Identity drift** (slug drift, model-text `file`) is untouched by hunk overlap; `persisted-by-construction` inherits the `file` error class (#75).
8. **"Beside the miss rate"** — there is no published miss rate; `flip_rate` as a new scoreboard key passes the web validator but needs a prereg definition and the reland fix before the public page. Check-run wording: no `stale`, no "miss rate" in summary, no `failure` annotation level.
9. **Wire**: any new per-reason field needs the two-PR accept-then-emit sequence (web validator first, api second); `Reason.file` is already off-wire for that reason.
10. **Receipt/MCP shape**: `ReceiptConvergence` and `get_convergence` payload gain states before any consumer exists — amend by addendum.
