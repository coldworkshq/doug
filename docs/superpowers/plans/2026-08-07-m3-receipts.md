# M3 Receipts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `GET /v1/prs/{pr_number}/receipt` — a tenant-scoped, evidentiary
record of what Doug said about one pull request, which instrument said it, how
much of the change that instrument saw, and what the repository did next.

**Architecture:** Pre-registration §2.1's governing-verdict rule is extracted
into one `store.governing_verdict()` selector, tested against §2.2's SQL
verbatim, so the receipt and the future published number cannot diverge.
Migration 8 adds three columns that let the receipt state instrument identity
honestly. The endpoint reuses `/v1/queue`'s dual-token structure.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy Core, pytest, `uv`. Postgres in
production, **sqlite in every test**.

```python
# If this string must change to make a test pass, the LOCKED pre-registration

GOVERNING_SQL = """
WITH ranked AS (
  SELECT v.installation_id, v.github_repo_id, v.pr_number, v.band, v.id,
         row_number() OVER (
           PARTITION BY v.installation_id, v.github_repo_id, v.pr_number
           ORDER BY v.scored_at DESC, v.id DESC
         ) AS rn
  FROM verdicts v
  JOIN outcome_jobs j
    ON  j.installation_id = v.installation_id
    AND j.github_repo_id  = v.github_repo_id
    AND j.pr_number       = v.pr_number
  WHERE v.tier = 'reader'
    AND v.scored_at <= j.merged_at
    AND j.window_days = :window
    AND EXISTS (
      SELECT 1 FROM installations i
      WHERE i.installation_id = j.installation_id
    )
)
SELECT id FROM ranked WHERE rn = 1
"""
```

```python
def governing_verdict(
    installation_id: int,
    github_repo_id: int,
    pr_number: int,
    merged_at: datetime,
) -> dict | None:
    """The verdict that was standing when a human chose to merge.

    THIS IMPLEMENTS A PRE-REGISTERED METRIC RULE. publication-preregistration.md
    is LOCKED v8; §2.1 defines this selection and §2.2 holds the SQL the
    published quarterly number runs. Editing this function changes a published
    number. The receipt endpoint and the future publication query must both
    call it, so that a customer's receipt cannot contradict the public table.

    Three details come from §2.2's SQL rather than §2.1's prose:
      * tier='reader' filters BEFORE the ranking, so a later deterministic
        fallback cannot displace an earlier real read.
      * band is NOT part of selection — it qualifies the denominator in the
        outer query. A flagged PR has a governing verdict and gets a receipt.
      * the installation must still exist, so a receipt cannot outlive the
        ledger row that scopes it.

    row_number(), never DISTINCT ON: the latter is Postgres-only and every
    test here runs sqlite (REVIEWING.md:141-143).
    """
    engine = _get_engine()
    if engine is None:
        return None
    ranked = (
        select(
            verdicts,
            func.row_number()
            .over(
                partition_by=(
                    verdicts.c.installation_id,
                    verdicts.c.github_repo_id,
                    verdicts.c.pr_number,
                ),
                order_by=(verdicts.c.scored_at.desc(), verdicts.c.id.desc()),
            )
            .label("rn"),
        )
        .where(
            verdicts.c.installation_id == installation_id,
            verdicts.c.github_repo_id == github_repo_id,
            verdicts.c.pr_number == pr_number,
            verdicts.c.tier == "reader",
            verdicts.c.scored_at <= merged_at,
            exists(
                select(1).where(
```

```python
def receipt(installation_id: int, github_repo_id: int, pr_number: int) -> dict | None:
    """Everything one PR's receipt states, assembled from the ledger.

    Merges are a LIST because uq_outcome_job includes merge_commit_sha, so the
    schema permits a PR to carry more than one merge identity — which is why
    §2.2 counts with count(DISTINCT pr_number). Adjudication nests under its
    merge so the document always names which merge it is talking about.

    latest_verdict and governing_verdict are separate fields, not one field
    with a flag: when they differ, work landed after the advice the merge was
    actually made on, and that difference is the thing a reader of an incident
    review needs to see.
    """
    engine = _get_engine()
    if engine is None:
        return None
    with engine.begin() as conn:
        latest = (
            conn.execute(
                select(verdicts)
                .where(
                    verdicts.c.installation_id == installation_id,
                    verdicts.c.github_repo_id == github_repo_id,
                    verdicts.c.pr_number == pr_number,
                )
                .order_by(verdicts.c.scored_at.desc(), verdicts.c.id.desc())
                .limit(1)
            )
            .mappings()
            .first()
        )
        jobs = (
            conn.execute(
                select(outcome_jobs)
                .where(
                    outcome_jobs.c.installation_id == installation_id,
                    outcome_jobs.c.github_repo_id == github_repo_id,
                    outcome_jobs.c.pr_number == pr_number,
                )
                .order_by(outcome_jobs.c.merged_at, outcome_jobs.c.window_days)
            )
            .mappings()
            .all()
        )
        outcome_rows = (
            conn.execute(
                select(outcomes).where(
                    outcomes.c.installation_id == installation_id,
                    outcomes.c.github_repo_id == github_repo_id,
                    outcomes.c.pr_number == pr_number,
                )
            )
            .mappings()
            .all()
        )
        latest_bundle = (
            {**dict(latest), **_verdict_bundle(conn, latest)} if latest else None
        )
    if latest is None and not jobs:
        return None

    by_outcome = {
        (o["merge_commit_sha"], o["window_days"]): o for o in outcome_rows
    }
    merges: list[dict] = []
    for job in jobs:
        key = job["merge_commit_sha"]
        current = next((m for m in merges if m["merge_commit_sha"] == key), None)
        if current is None:
            current = {
                "merge_commit_sha": key,
                "merged_at": job["merged_at"],
                "base_ref": job["base_ref"],
                "merged_head_sha": job["merged_head_sha"],
                "governing_verdict": governing_verdict(
                    installation_id, github_repo_id, pr_number, job["merged_at"]
                ),
                "adjudication": [],
            }
            merges.append(current)
        outcome = by_outcome.get((key, job["window_days"]))
        current["adjudication"].append(
            {
                "window_days": job["window_days"],
                "status": job["status"],
                "due_at": job["due_at"],
                "kind": outcome["kind"] if outcome else None,
                "observed_at": outcome["observed_at"] if outcome else None,
                "source": outcome["source"] if outcome else None,
                "detail": _obj_or_none(outcome["detail"]) if outcome else None,
            }
        )
    return {"latest_verdict": latest_bundle, "merges": merges}
```

```python
@app.get("/v1/prs/{pr_number}/receipt")
def pr_receipt(
    pr_number: int,
    repo: str,
    x_doug_token: str = Header(""),
) -> ReceiptResponse:
    """One PR's evidentiary record.

    `repo` is required: a PR number alone is ambiguous across repositories.
    Scoping mirrors /v1/queue exactly — the operator token is unscoped, a
    dispensed token must carry receipt:read and the repo must be inside its
    live-intersected selection. Out-of-scope and nonexistent both return 404,
    so a caller cannot tell "not yours" from "not there".
    """
    expected = os.environ.get("DOUG_API_TOKEN")
    if not expected:
        raise HTTPException(status_code=503, detail="DOUG_API_TOKEN not configured")
    if not store.enabled():
        raise HTTPException(status_code=503, detail="no ledger configured")

    installation_id: int | None = None
    if not hmac.compare_digest(x_doug_token, expected):
        try:
            ctx = tenancy.resolve(x_doug_token)
        except tenancy.KeysNotConfigured as e:
            raise HTTPException(status_code=503, detail="token verification not configured") from e
        if ctx is None or "receipt:read" not in ctx.scopes:
            raise HTTPException(status_code=401, detail="bad token")
        installation_id = ctx.installation_id
        live = {full_name: rid for rid, full_name in store.active_repos(installation_id)}
        rid = live.get(repo)
        effective = ctx.repo_ids if ctx.repo_ids is not None else frozenset(live.values())
        if rid is None or rid not in effective:
            raise _not_found()
        repo_id = rid
    else:
        resolved = store.repo_id_for(repo)
        if resolved is None:
            raise _not_found()
        installation_id, repo_id = resolved

    data = store.receipt(installation_id, repo_id, pr_number)
    if data is None:
        raise _not_found()
    return _receipt_response(repo, pr_number, data)
```

`NULL`, so a consumer cannot mistake absence for a value.
